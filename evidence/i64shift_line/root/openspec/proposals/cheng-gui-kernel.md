# Cheng GUI 内核收口：交互与布局层统一重设计（渲染层保留）

状态：**propose**（2026-06-12 用户方向确认"需要设计良好的不低于原生性能的纯 Cheng GUI"；本提案划定范围）。

## 一页结论

渲染层（compositor/layer cache/SDF 字形/媒体纹理）实测 68-73fps、墨效 11ms 帧距，retained tree+GPU 合成与原生同构——**保留不动**。需要重设计的是从快照模型上长出来的交互层与布局层：hitRect 表无 z、route/event/text 三套分离 O(n) 扫描、运行时无增量 relayout。2026-06-12 的连环事故（点击穿透、点击卡死、转场失败阻塞切换、三个 cold let-快照规避散布在生成器）全部源于"交互语义没有单一事实源"。

> 同 v2 总纲原则：一个语义一个事实源。交互目标（点击去哪、事件给谁、焦点落谁）必须是一张表、一次查询；布局必须是一个增量引擎、一种失效协议。

## 三章设计

### 1. 统一交互模型
- **一张交互目标表**：build 期把 route edge / event handler / text input 合并为 `InteractionTarget{nodeId, kind, payload}`，按 nodeId 排序数组+二分（cold 安全，无哈希依赖）。
- **空间索引**：layoutBoxes 按 (routeIndex, layerId) 分段 + 段内按文档序；hit 只扫活动路由段（28K→~600），按 (layer desc, boxIndex desc) 首命中即赢家——z 仲裁成为结构性质而非补丁。
- **单次查询协议**：up 事件一次 `TopInteraction(x,y) → {kind, nodeId}`，直通对应 apply；hitRect 烘焙表退役（z 信息缺失，2026-06-12 穿透事故根源）。
- 性能门：点击响应（up→present 提交）P95 < 10ms。

### 2. 增量布局
- 运行时 relayout 入口：`RelayoutSubtree(nodeId)`——文本变化/可见性切换只重排局部子树，替代"glyph run 原位重写"hack（M2 容量化重绑的临时形态）。
- 失效协议单一：状态变化 → 标脏节点集 → 帧内一次 relayout + 一次 paint 增量。
- 性能门：单卡片文本变更 relayout < 2ms；列表整页重绑 < 8ms。

### 3. 帧管线契约
- 每帧固定顺序：输入消费 → 状态同步（转译槽镜像）→ 增量布局 → 增量绘制 → present。
- 预算显式（@120Hz）：输入 0.5ms / 布局 2ms / 绘制 4ms；超预算打 findings 计数器（不静默）。
- 转场（水墨）是装饰层：失败回退直切（已实现 v176），永不阻塞切换。

## 与转译线的关系

GUI 内核接口（节点树 + 状态驱动增量更新）就是转译产物（M3 全组件）的渲染目标 API。先收口内核，M3 直接落在干净接口上。M2 已验证的反应链（状态槽→重算→重绑）语义不变，重绑实现升级为增量布局调用。

## 阶段与门禁

| 阶段 | 内容 | 门禁 |
|---|---|---|
| K1 交互表+空间索引 | 合一目标表、活动路由段索引、单次查询、hitRect 退役 | 真机点击 P95<10ms；全交互回归脚本（卡片/返回/排序/搜索/tab/back）全过 |
| K2 增量布局 | RelayoutSubtree + 失效协议；重绑切到 relayout | 单变更<2ms、整页<8ms；digest 44/44 不回退 |
| K3 帧契约+预算 | 阶段计时+超额报警；切页预热 | 切页 P95<50ms；像素 oracle 不低于基线 |

## 不做什么

不动渲染层；不引入新绘制后端；不在内核内嵌业务语义（转译产物只经接口调用）。

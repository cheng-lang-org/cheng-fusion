# FS Capability Bootstrap

This document is intentionally short because the old weak-stub bootstrap plan
has been retired.

Production Cheng/Codex linking must use explicit real provider objects. Missing
filesystem, process, SQLite, HTTP, model, socket, or websocket symbols are
compiler/link errors, not weak-stub opportunities.

Rules:

- Do not compile `src/core/runtime/host_runtime_stubs.c`.
- Do not add weak C symbols to make provider-free binaries link.
- Do not route missing FS capability through `bootstrap/host_runtime.c`.
- Add real provider coverage in `codex/support/*_provider.c` or Cheng runtime
  provider modules under `src/core/runtime/`.
- Keep no-provider `@importc` paths hard-failing with
  `cold_macho_explicit_provider_required`.

The current gap report is generated by `tools/host_runtime_gap_report.sh`.

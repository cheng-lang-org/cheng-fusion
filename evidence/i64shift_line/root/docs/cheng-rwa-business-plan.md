## 0. 一句话

**Cheng 写整条可验证执行栈；RWAD 是这套栈上的净值份额度量衡；UniMaker 把度量衡落到真实交易、内容和机器结算。**

不是再发一条公链讲故事，也不是再做一个“1 枚 = 1 美元”的稳定币。要卖的是：报价、托管、交付回执、批次清算、异议冲正、储备证明，全部能重放、能追责。

## 1. 执行摘要

现实世界资产上链的失败模式几乎一样：链上有代币，链下没有可审计交付；价格来自做市商报价，不来自成交与回执；激励靠无抵押增发，最后稀释自己。

本计划把三块已经各自存在的资产接成一条商业闭环：

| 层 | 是什么 | 商业角色 |
|---|---|---|
| Cheng | 可自举系统语言与编译器，确定性内存，多端原生代码生成 | 基础设施与护城河；开源获开发者和模型采用 |
| RWAD | 国库净值（NAV）份额单位 + 结算状态机 | 统一计价与结算；铸造必须绑储备证明 |
| UniMaker | 跨端制作器 / 社交 / 内容 / 钱包 / NFC / C2C | 获客与成交入口；手续费发生在这里 |

已验证的技术事实（2026-08，绑定仓库证据，不是市场数据）：

- RWAD 链内核四件套已定案并有 smoke：LSMR 账本格、serial/nullifier 累加器、DAG 全序、最终性证书。经济模块（结算、预言机风控、桥、治理、储备纪律）已迁入 `cheng-lang/src/apps/rwad/`，跨仓运行时依赖废止。功能闭环登记 27 条 smoke，DoD1–5 标记为 met。
- UniMaker 产品面已有 RWAD 钱包导入、链上余额拉取、NFC 点对点转账、积分/RWAD 双轨、C2C 托管开关、VPN 节点按 RWAD/GB 计费。
- 产品规格已写清：默认 ETF 篮子 BTC∶黄金∶港元稳定币 = 1∶1∶1；入金走稳定币换仓，铸造走储备证明，不按二级市场价格增发。
- Cheng 自举链 stage0→stage3 合同槽 `e202c0c35424eb36` 在位，官方 `ci_gate` 9/9。**不得把该合同槽说成“纯 Cheng 编译产物”**：现行 stage3 仍含 C 冷锚（`cheng_cold.c`），零 C 未完成。

未验证、本计划不假装已有：付费用户、经常性收入、持牌主体、实物黄金 Allocated 入库、面向公众的代币交易、公测留存。2026-02 路演里的阶段 0（2026-03 成立基金）已过期，时间表从 2026-09 重排。

融资主轮沙盘沿用既有路演：**自治组织基金 3000 万美元，24 个月，按里程碑拨付**，只列支出。口袋信物硬件验证轮（人民币 150 万）是另一份计划、另一笔账，禁止并入本轮。

成功判据（重排后，截止 2028-08-31）：

1. 至少一条法域跑通可收费闭环：目录 → 报价 → 托管 → 回执 → 批次清算 → 异议冲正。
2. 付费企业客户 60 家（跨境电商 / 供应链 / 内容电商）。
3. 争议平均闭环 72 小时。
4. 可验证资产目录 10000 条（订单、仓单、应收、内容权利）。
5. 四条资金流（创作者、Agent、DePIN、储备纪律）各自有五段哈希链对账单，且奖励发放 ≤ 手续费+罚没，无抵押增发为零。

## 2. 问题

**对账断、证据碎。** 跨境订单、仓单、应收、内容分润今天仍靠邮件、截图和平台后台。纠纷成本高于货值是常态。

**规则不透明、迁移贵。** 平台单方改费率、改推荐、改裁决。创作者和商家被锁定在流量分发规则里，净留存被抽走 10%–55%（Patreon / YouTube / 应用商店公开口径）。

**链上 RWA 多数是凭证，不是结算。** 把资产“映射”成代币很容易；把交付回执、挑战窗、冲正、储备证明做成同一套状态机很难。没有回执的价格发现是做市，不是市场。

**机器交易没有度量衡。** Agent 之间按次、按秒、按调用付费，用 ETH/SOL 计价会把预算控制交给币价波动。需要整数单位、可预测费用、escrow、幂等、软确认与硬终局分层。

**跨端开发税。** 同一套结算和钱包逻辑今天要写三遍。脚本引擎、GC、JS↔Native 桥是秒开和微支付的隐性成本。没有自有语言，结算栈最终还是别人的运行时。

## 3. 机会与定位

机会不在“再做一个交易所”，而在把 **可验证交付** 做成价格发现的唯一输入。

定位三句话：

1. **RWAD 是尺，不是锚死美元的钞。** 不承诺 1 RWAD = 1 美元，不承诺固定法币兑付。铸造/赎回看净值与 `reserve_proof_hash`；成交价看可执行报价。
2. **UniMaker 是把尺用起来的地方。** 内容发布、C2C、NFC 当面交割、跨境订单、Agent 调用，统一用 RWAD 计价，积分只做不可流通的贡献凭证。
3. **Cheng 是尺和尺子工厂都用同一种金属。** 链内核、状态机、钱包适配、移动壳、点对点网络用同一门语言写，证据绑定源码哈希，而不是“合约一层、App 一层、运维一层”各说各话。

标志性首笔成交的业务意义：证明“链上报价 → 现实交付回执 → 批次入账”闭环成立，并为中位价和风控参数提供第一批可复核样本。它是价格发现的点火，不是营销事件。

## 4. 产品

### 4.1 Cheng：系统语言底座

面向系统软件、编译器、网络、加密和结算内核。已有事实：

- 自举链与合同槽在位；官方 CI 门禁通过。
- 多端后端（含 ARM64 Android / 鸿蒙宿主生成）和自研协议栈（QUIC/TLS、libp2p、VPN 传输）已在真机路径上跑过。
- 所有权 / ORC 是一等语义：托管值禁止位拷贝冒充完成。RWAD 会话本身就是这套纪律的压力测试（跨 Result 搬 `str`、构造器 sret 双所有权已立案）。
- 后量子套件（ML-KEM / ML-DSA / SLH-DSA）有 NIST KAT 门禁；签名算法标识预留升级，服务“密码学敏捷”。

诚实缺口：零 C 未完成；热路径相对冷路径仍有数量级差距（历史记录约 229×，以当前实测为准，不把旧倍率当卖点）；纯 Cheng 自举固定点尚未存在。这些走软件主轮，不从 RWA 持牌预算里抽。

### 4.2 RWAD：净值份额与结算操作系统

白皮书 0.4.1（2026-03-18）与链架构定案（2026-08）对齐后的产品定义：

- **单位**：链上整数记账，最小单位 1 RWAD，不另设小数。微支付靠创世供给尺度，不靠“再切 18 位”。
- **供给纪律**：只有可证明的储备净值增加才能铸造。二级市场价格上涨不是铸造依据。奖励默认走积分轨道，兑换来自费用池 / 罚没池 / 已预算生态基金。
- **储备设想**：比特币、实物黄金（成交与 Allocated 入库分状态）、港元稳定币流动性缓冲。默认 ETF 换仓权重 1∶1∶1，可治理。黄金未入库头寸按折扣或不计入 NAV。
- **结算语义**（内容、电商、本地生活共用）：`OrderCreated → EscrowLocked → DeliveryReceiptSubmitted → ChallengeWindow → BatchFinalized → EscrowReleased`。挑战成立用新批次冲正，不删历史。
- **两层价格**：预言机估值只做风控护栏；可执行报价决定成交。偏离护栏触发限额、延迟释放、人工复核。
- **储备风控已写进内核**：铸造必须匹配 `reserve_proof_hash`；信用额度默认上限 5%、TTL 7 天，超期冻结。无抵押超发在状态机里直接拒绝。

链架构（权威：`docs/rwad-chain-architecture.md`）：

1. LSMR 账本格：每账户一条事件链，转账双父锚定。
2. 全局 accumulator：支付事件必须登记 serial/nullifier，根进区块摘要。
3. DAG 全序 + 委员会 2f+1。
4. 最终性证书：轻节点只验证书和 checkpoint，不重放全图。

干支时钟已撤案，不承担共识或经济语义。

### 4.3 UniMaker：成交与证据入口

不是“又一个短视频 App”，是把上述结算语义接到人能用的界面：

| 模块 | 现在能指到的产品事实 | 商业含义 |
|---|---|---|
| 发布与内容市场 | 内容 CID 上链登记，上架走 P2P，结算走 escrow；资产 Token 可跨应用持有 | 创作者确权、点映、二级版税 |
| 积分 / RWAD 双轨 | 资料页同时有积分与 RWAD；境外账号仅支持 RWAD 充值 | 贡献奖励不稀释供给 |
| 钱包 | 导入 RWAD 钱包、拉链上余额、缓存与失败提示 | 用户侧余额以链为准 |
| NFC 当面交割 | Android Host Card Emulation + 结算模式（真实原子确认 2 次） | 线下交付的物理回执 |
| C2C | `c2c_rwads_v2` 特性开关，广告+钱包+托管 | 点对点资产交易入口 |
| 节点服务 | VPN 节点按 RWAD/GB 报价 | DePIN 计费的产品壳 |
| 端侧智能体 | 发布事件映射为知识/技能/素材，再进 `receipt → batch → challenge → finalize` | 内容变成可结算能力增量 |

明确不做：把评估板当商品零售、把硬件验证轮资金并进本计划、在中国大陆向公众做代币交易或募资。

## 5. 四条可造血资金流

商业闭环的判定不是 TVL，是这四条流各自能拿出对账单：`input receipts hash → batch merkle root → txHash → 分账明细 → 余额变化`。

**E1 创作者流。** 质押发布 → 引用/播放/点映产生 usage receipt → 批次 Merkle-Sum → 挑战窗 → finalize → escrow 分账。奖励先积分，周期兑换。刷量、重复发布、假引用走指纹、延迟结算和扣罚。

**E2 Agent 付费流。** 402 式报价–付款–回执。小额看软确认继续执行，大额等硬终局。失败走冲正，禁止“先做事后口头算”。费用可设上限、可幂等，避免机器重试双花。

**E3 DePIN 算力/带宽流。** 推理计量和 VPN 流量已有提交/finalize 门禁和产品报价位。结算入链，按服务等级对齐，不靠口头补贴。

**E4 储备纪律流。** 用户 USDT/USDC 入金 → DEX 三腿换仓（BTC / 黄金 / 港元稳定币）→ 托管快照 → `reserve_proof_hash` 挑战通过 → 按 NAV 份额铸造。黄金“已成交未入库”不得直接当已铸造依据。第一期自定义比例只是买入偏好，不承诺子基金隔离。

激励铁律：任一周期 `reward_pool` 发放 ≤ `fee_pool + 罚没`。做不到这一条，RWAD 就退回成通胀积分，计划作废。

## 6. 市场与竞品

不写未调研的 TAM 绝对数。沟通用两类口径：

- **可计费费用池**：内容与交易结算、托管与争议、节点与平台服务。市值叙事只作空间上限，估值落地看经常性收入倍数。
- **价格发现**：同类资产有效成交中位价。有效成交 = 交付回执完成 + 挑战窗通过。

对照（公开费率，2026-02-06 路演口径，代表类目成交手续费，不含投流/物流/分期）：

| 领域 | 代表费率 | UniMaker / RWAD 怎么比 |
|---|---|---|
| 国内带货（淘宝/京东/小红书） | 0.6% | 沙盘统一 2%，但绑定回执、异议、冲正，不绑单一流量分发 |
| 抖音部分非标 | 5% | 费率更低，规则可审计 |
| 亚马逊家居厨具 | 15% | 跨境抽成更低，证据链跨法域 |
| 苹果应用商店 | 30%（满一年订阅 15%） | 用成交抽成替代货架税 |
| 谷歌应用商店 | 15%–30% | 同上 |
| Patreon | 10%+支付通道 | 创作者净留存更高 |
| YouTube 广告 | 平台留存 45%–55% | 不靠广告分成活 |
| Uniswap 基准档 | 0.30% | 不只比费率，比一比一映射和交付纠错 |
| dYdX / GMX | 数个基点 | 机构要的是回执和赎回，不是永续深度 |

语言层对照：Rust / Zig / Swift 都不以“多端原生 + 自举验证 + 结算状态机同一语言”为设计起点。应用层对照：小程序锁平台，Flutter 抹平渲染不消灭桥税，v0/Bolt 生成 Web 后再套一层框架。RWA 层对照：多数项目停在“代币化凭证 + 法币稳定币入金”，没有 NAV 铸造纪律，也没有产品级 NFC/C2C/内容结算。

本计划的差异是纵向整合，不是单点费率更低。市场是否买单，只能用公测转化验证，现在没有付费数据。

## 7. 商业模式

收入只认三类，全部汇总为成交抽成（沙盘费率 2%，试点复盘后锁定单一公开费率，不用区间对外）：

1. 内容带货与点映  
2. 跨境电商与订单结算  
3. 现实资产映射结算（铸造/赎回费、托管争议、DEX 换仓费另计协议费，不与 2% 混写成“大概”）

估算方法（有占比和费率再填数，本版不填收入绝对值）：

`预计手续费 = 各领域可服务市场 × 目标份额 × 统一费率`

语言开源，钱收在产品和企业层：

| 层 | 收 | 不收 |
|---|---|---|
| Cheng 公开树 | 不收。规范、可出口的编译器树走 OSI | 把自举敏感层和未出口源码当商品挂到美国 GitHub 当事主 |
| UniMaker 个人 | 公测后：额度、主题、多设备、加速构建 | 用评估板加价当主营 |
| UniMaker 企业 | 私有部署、SLA、争议仲裁、对账 API | 为单一客户改结算协议 |
| RWAD 协议 | 铸造/赎回、DEX、预言机、跨链、争议服务 | 无抵押增发当收入 |
| 节点 | 索引、轻节点证明、带宽按 SLA | 用通胀补贴伪装成收入 |

质量指标：收费客户续费率、争议闭环时长、单笔结算毛利、账务纠错率、报价成交率、交付完成率、挑战成功率、冲正率、复购率。

## 8. 合规与法人：四条线不能装进同一家公司

权威备忘：`docs/承道合一出海合规架构.md`（2026-08-21）。落地以持牌律师备忘录为准。

三条原则：

1. 境内基础设施、个人信息、重要数据留境内。出海卖许可和交付能力，不把资产搬家。
2. 新加坡必须有人、有租、有账、有决策。空壳加开曼控股按实质穿透。
3. 开曼基金是外部资本工具，不是开源协议所有人，也不能绕 ODI 买境内股权。

推荐中间形态：

```
承道合一（境内产业母体）
    │ 可撤销独家许可：对象代码 / SDK / 文档
    ▼
新加坡 Steward（CLG，无股本）—— 开源许可、商标、规范冻结
新加坡 Commercial HoldCo（Pte Ltd）
    ├── Cheng Tech Pte     许可、支持、认证
    ├── UniMaker Pte       产品与分发
    └── Embodied Pte       海外集成，美国不控
开曼 Tech Fund  —— 只买 HoldCo 股权
开曼 RWA Fund   —— 只持受 MAS / 证监会路径约束的代币化产品
```

法域角色（路演匹配度，未变）：

| 地区 | 角色 | 匹配 | 红线 |
|---|---|---|---|
| 迪拜 | 基金与中东机构 RWA 入口 | 9/10 | 实体经营、制裁、银行关系前置 |
| 新加坡 | 东南亚总部、支付合规中台 | 8/10 | 牌照贵，KYC/AML 必须产品化 |
| 香港 | 机构合作与 RWA 试验 | 8/10 | 零售功能默认关 |
| 深圳 | 研发与供应链交付 | 7/10 | 大陆不做公募代币交易；数据本地化 |
| 海南 | 跨境贸易与数据试点 | 7/10 | 跟园区和持牌机构共建，不自开交易所 |

大陆产品边界：只做订单、回执、证据哈希、争议仲裁语义；跨境只同步摘要。编译器禁止内置“一键铸币”。RWA 钱包、合约运维、境内用户账号不出开源树。

策略按分组编号分轨，不做全球一刀切。门禁分索引门禁和访问门禁。争议：评审池抽样，委员会兜底。风控：限额、冻结、延迟释放、按资产腿/桥通道/法域暂停。

## 12. 风险与对策

| 风险 | 为什么真实 | 对策 |
|---|---|---|
| 合规 | 多法域虚拟资产；大陆禁止公募代币 | 分轨开关、持牌伙伴、RWA 单独法人和基金 |
| 供给纪律被突破 | 按市价铸造或积分直接变 RWAD 会毁度量衡 | 内核拒绝无证明铸造；奖励只走积分+预算 |
| 黄金交割延迟 | 成交 ≠ Allocated | 分状态；未入库折扣或不计 NAV；宁可延迟铸造 |
| 托管与对手方 | 实物和稳定币都有冻结/违约 | 多托管、限额、通道级暂停、披露节奏 |
| 预言机 | 估值被操纵或过期 | 多源、偏离过滤、过期降级、喂价质押与扣罚 |
| 技术 | 零 C 未完成；ref10 `-B` 与外部 Ed25519 不互通；ORC 编译器债 | 对外互操作前先做 epoch 迁移；内部流转必须标注约定；编译器债单独立项 |
| 安全 | 自研加密与网络，不能借 OpenSSL 声誉 | 公测前第三方审计；多签轮换；演练归档 |
| 商业 | 无付费用户 | 先验证免费到付费转化，再扩销售编制 |
| 治理 | 大户改参、女巫刷积分 | 时间锁、延迟结算、设备风控、申诉经济 |
| 出口管制 | 编译器/Agent 挂公网视为技术出口 | 先分类再镜像；未许可层不上公开树 |
| 量子 | 现有签名长期可能失效 | 算法标识 + 双栈迁移窗口，不承诺已抗量子 |

## 15. 结语

Cheng 解决的是“谁来写、如何证明写对了”。  
RWAD 解决的是“用什么尺记账，尺会不会被偷偷放长”。  
UniMaker 解决的是“谁在什么场景里愿意按这把尺成交”。

三件事拆开都是故事；合成一条可重放的资金流，才是生意。先跑通可收费闭环，再复制法域。融资只为这件事服务。

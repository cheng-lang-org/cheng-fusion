# 纯 Cheng 原生分布式编译器 · 方向草案（2026-09-16）

> 命题：纯 Cheng 编译器自包含于 Cheng libp2p 之中，成为原生分布式编译器。
> 性质：方向草案（非施工单）。插入点 = M1-M4 里程碑之后；当前冻结窗口（打穿 typed-facts）不受影响。

## 一、第一性原理：为什么这个命题在现役资产上是「顺流而下」

分布式编译的正确切口不是「把编译器搬到分布式系统上」，而是**编译器本身成为内容寻址网络中的一个可验证服务**。四个地基已在案：

| 地基 | 现役资产 | 分布式含义 |
|---|---|---|
| 确定性编译 | 字节级固定点三轮回执、GEN2/GEN3 自烤 sha 对拍、L1 exe 收据路径无关（v3→v4） | 任意节点编译任意分片，产物逐字节可对拍——分布式一致性问题被编译确定性消解 |
| 内容寻址 | `src/libp2p/cas_store.cheng`（CAS）、`crypto/hash256`、`bytes_layout` | 源码字节与编译产物按内容寻址，传输与验证合一 |
| 事实合同 | CSG 快照/merkle_transaction/cid_identity、facts⊕bytes 框架 | 交换物不是「编译请求」而是事实与字节；merkle 回执天然防篡改 |
| 自宿主闭环 | 234 源闭包、stage3 冻结载具、跨代自烤 | 编译器验证自己的机制已存在，分布式化 = 该闭环多节点化 |

**「自包含」的精确定义**：一个编译器版本 = 234 源闭包字节 + 其全部编译产物的 merkle root（CID）。持有该 CID 的节点从 CAS 同步块即获得完整可运行编译器——编译器本身是它自己网络中的一个内容对象。

## 二、三层形态

- **L1 自包含**：编译器闭包 + 产物入 CAS；版本 = merkle root CID。自宿主固定点（GEN2/GEN3）即「该 CID 的编译器能编译出字节相同的自己」的可验证断言。
- **L2 分发同步**：libp2p 节点间 CAS 块同步（bitswap 式）。无中心分发者；块的完整性由 CID 内蕴验证。
- **L3 分布式编译**：编译任务 = (源闭包子集, 目标) → 分片到持同版本编译器的节点 → 产物回传 → merkle 聚合。并林窗（当前最大相，逐源 append）天然可按源分片；C2 免重解析（−55.3s 已落）即分片复用的雏形。

## 三、依赖与插入点

| 依赖 | 现状 |
|---|---|
| M1 墙清偿（GEN2/GEN3 rc=0） | 冻结窗口打穿中——每个节点跑的必须是稳定的纯 Cheng 编译器 |
| M3 内存贴线 768MiB | 节点资源约束的软版本 |
| M4 时间档 L1 199-209s | 单节点基线——分布式收益 = 并林窗分片（最大相），量化目标可由此推 |
| 缺口 | libp2p 节点发现/传输协议/任务调度三件未建（cas_store 只是存储原语） |

插入顺序建议：M1 打穿 → GEN2/GEN3 固定点入 CAS（L1 闭环最小验证）→ L2 同步协议 → L3 并林分片。**不与 M2/M3/M4 争资源**——它们全部是分布式的前置而非竞争者。

## 四、风险与纪律延伸

1. **确定性纪律延伸**：分布式引入调度/网络/缓存新非确定性面——内存模型约束卡的「读数同窗口相对比较」「逐相贴线」须延伸为「跨节点同版本对拍」口径。
2. **CAS 一致性**：cas_store 现为单机原语；多节点并发写同一 CID 块的幂等性需在 L2 设计期钉死（块不可变 ⇒ 天然幂等，但 GC 与引用计数要设计）。
3. **安全面**：merkle 验证已有，但节点身份与恶意分片产物（字节对但语义错——不可能，因确定性；字节错——CID 不匹配即拒）在确定性前提下威胁面极小——这是确定性编译给分布式的最大安全红利。
4. **禁 Mock**：L2/L3 的节点协议必须真实现（真机回执），不得仿真层冒充（vpn/捕鱼战役先例）。

# CSG语义视频播放器执行扩展草案

版本为0.2草案，日期为2026年9月17日。本文规定语义视频记录如何驱动世界播放器，以及实际执行、呈现和重演如何绑定同一版本。用于工程设计和互操作测试设计，尚未冻结线格式，尚未实现或通过互操作验收。

本扩展连接源视频、语义对象、可执行世界、交互契约和播放器。目标是让播放器查询的对象、操作的对象和显示的状态有精确对应，防止错误世界、旧帧和未经观测的参数被当成当前视频事实。

## 1 版本与适用范围

沿用CSG核心编码、资源身份及验证规则。冻结的[语义视频v0.1](csg-semantic-video-v0.1.md)第1至6节及其能力表保持原样。本文中的逻辑记录名不是已注册kind、字段或错误码，不能据此生成声称v0.1合规的新记录。

新必需记录在后续冻结的独立扩展命名空间中编码，外层执行入口以内容身份引用原v0.1块和扩展块。播放器先验证执行入口所要求的扩展；旧读取端可以独立读取原v0.1内容，但不得忽略扩展后声明已满足世界视频执行请求。必需执行条件不得放入可忽略的x-字段。

基础执行扩展规定可观察行为，不强制所有实现采用状态商模型。按交互契约合并与细化属于独立算法配置，启用时必须明确声明、验证并进行专利对照。标准合规、已实现、自有专利覆盖及第三方实施自由分别判定。

## 2 内容与执行身份

执行入口必须绑定完整源资源CID、语义记录块CID、世界定义CID、模型版本、资产闭包、执行程序版本、数值配置、时间映射、交互契约和初始恢复状态。每一必需资源具有类型、长度和内容身份，并检查实际取得字节与声明一致。名称、路径、短哈希前缀或仅最终状态链摘要不能替代完整身份。

对象绑定表将源语义对象的命名空间、世代及编号精确映射到世界版本中的实体身份，记录适用时间段、空间区域、标定和来源类别。同一可操作对象不能仅凭名称或相似度在执行时重新选择。进程内索引仅作为已验证映射的实现形式，不能作为跨包身份。

资产数量、网格元素、解码缓冲和求解器工作区均在分配前受预算约束。首个实现只允许已登记、具有精确输入输出合同的执行配置；内容包不能凭格式验证自行获得任意本机代码执行权。

## 3 时间与来源

源媒体PTS、必要解码顺序、世界tick和呈现时钟分别记录。映射使用有理时间基、起点和明确舍入规则，乘加前检查溢出。变帧率、非零起点、B帧、音频预滚、设备时钟漂移不能用帧号近似为同一时间。

原片观测、推断属性、人工参数和模拟结果保留来源区别。播放器仅在适用时段和已验证对象上使用观测约束。未知质量、遮挡几何、尺度或摩擦不能通过赋默认值变成已观测事实。内容允许用户明确选择假设并建立模拟分支，其结果归属于该分支。

每种状态自由度在每个执行区间只有一个权威更新来源。原片轨迹与求解器不能同时写入同一状态；从轨迹控制切换到仿真前应恢复该模型所需完整状态，记录交接边界及父分支。

## 4 逻辑记录与责任

| 逻辑记录 | 必须绑定的信息 | 消费方 |
|---|---|---|
| 执行入口 | 源记录、世界、程序、资源闭包、契约、时间和恢复状态 | 加载器 |
| 对象映射 | 源对象、世界对象、版本、时空范围、来源及标定 | 查询和动作分派器 |
| 交互请求 | 会话内唯一请求号、对象、动作参数、前置版本、权限、目标契约 | 准入与执行器 |
| 恢复单元 | 检查点、精确基态、随机及控制器状态、必要解码与渲染历史、资源依赖 | 恢复器 |
| 候选及细化记录 | 启用约简配置时的候选集、区分资料、划分和映射检查 | 状态细化器 |
| 执行提交 | 父版本、新契约、新状态、模型与全部执行资源版本 | 单一提交边界 |
| 呈现结果 | 提交版本、分支、逻辑时刻、相机、输出配置、实际帧与音频结果 | 呈现端 |
| 重演清单 | 完整初始配置、有序事件、检查点、执行与呈现比对策略 | 第二终端 |

动作请求失败时不消耗为成功动作；请求去重、失败结果和重试语义必须由冻结配置定义。上述记录需冻结字段布局、规范字节、摘要域和正反fixture后，才可以发布实现符合性声明。

## 5 加载与首帧

加载器验证入口及资源闭包，恢复目标时间的有效状态后，输出实际首帧。资源就绪、解码完成、渲染完成、提交显示和显示系统回报呈现分别记录，不能用“文件打开成功”代替首帧。平台只能提供提交回执时，记录级别明确为已提交，不声称已经上屏；画面帧摘要也不证明物理屏幕被观看。

冷端不假定素材、模型和程序已缓存。新执行入口应支持有界分块资源及可验证索引，先取完整首帧所需闭包；不能通过省略必要数据实现表面秒开。仅有整片资源摘要且缺少可验证分块时，应记录全量校验成本，不能把未经验证的局部源数据作为完整验证成功。

音画各自绑定同一提交版本及有理时间映射；不含音频的内容显式声明。GPU完成及显示、音频回调通过事件推进，暂停或等待资源时不忙轮询。物理步进可以使用明确的逻辑tick，但调度不等同于持续空转。

## 6 交互与状态细化

当前契约内的动作也必须验证对象、权限、前置状态和参数；验证通过才执行。新增动作或输出需求超出当前契约时，先检查模型域。更换物理规律或越过模型边界属于新模型版本，不能沿用同域细化证明。

启用交互约简配置时，由入口候选集重放实际历史并应用有效观测，恢复当前候选集合。独立检查新旧划分映射、旧动作及输出保持关系；候选集合非空且全部位于一个新类，才允许提交。跨多个新类时保留歧义；空集合报模型或观测冲突。任取代表、用模型自身输出充当新增现实证据均不合规。

用户明确选定假设时，新建带父分支及参数来源的模拟分支，再验证请求。原片画面及其补偿不得无条件覆盖交互后状态。分支和输出模式必须明确，不能把原片延续画面标成新动作的模拟结果。

## 7 提交与实际呈现

准入检查使用冻结的父版本。提交时在同一原子操作中检查父版本仍为当前版本并切换当前版本引用，使契约、模型、状态、资源和分支在同一发布边界生效；竞争失败重新基于新版本处理请求，不能沿用旧检查结果。

所有渲染及音频任务携带提交版本。新版本生效时，呈现队列清除或隔离尚未呈现的旧版本任务；已呈现的历史保持原版本记录，无法取消的旧任务回报为过期输出，不得记作新请求成功。不能只更新UI上的“能力就绪”而继续使用旧模型。

回执分为执行状态与呈现状态，记录实际消费的资源、前后状态、请求和提交版本、帧或音频结果及回报层级。执行成功但渲染或显示失败时，应分别记录，不能声称用户已看到结果。外部设备动作仍需独立授权、设备身份及实测回执，虚拟分支回执不替代现实执行证明。

## 8 跨端重演

第二终端验证完整世界、资产、程序、数值规则、初始状态和有序事件后重演。分别比较执行检查点及规定的呈现输出。只比较最终chainCid，不足以证明中途画面、相机、音频或真实上屏一致。

确定性输出配置要求对应帧和音频规范字节一致；允许误差的配置须事先定义比较域、算法及阈值，并只报告该标准下的一致性。两种配置不得互相替换。跨设备浮点或GPU差异没有验证前，不宣称任意设备同像素。

## 9 错误与验收

错误类别包括资源缺失或损坏、身份与版本冲突、时间映射失败、依赖不完整、未知执行配置、动作越界、候选为空、多类歧义、过期提交、过期呈现和预算不足。具体错误码等待线格式冻结；失败不能自动减小能力、降低质量或重新签发成功回执。

| 验收场景 | 必须观察的结果 |
|---|---|
| 存量视频中一个对象绑定到可执行世界 | 点击、查询、动作及呈现均指向同一有来源的对象 |
| 初次打开及随机跳播 | 真实首帧对应请求时刻；完整依赖可复核 |
| 新增冲量但质量未知 | 保留歧义；补证据或明确模拟假设后才执行 |
| 交互扩张期间切换版本 | 旧状态不能执行新能力，旧帧不能冒充新结果 |
| 两端重演及篡改资源反例 | 分别报告状态与输出比对；错误版本拒绝 |
| 变帧率、B帧、非零起始及音频预滚 | 时间映射与实际输出一致，不用帧号代替时间 |
| 冷缓存、取消、反复加载卸载、流中断 | 峰值及资源释放可测；缺口显式，不伪造连续性 |

## 10 实现现状与后续冻结

现有csg_player具有世界执行、渲染和事件重演代码；semantic_player具有记录验证、时间轴及源样本回读代码。后者未接通像素解码，且打开时全量读取源文件；两入口未完成本文接线。历史测试报告不等同本扩展通过。本次只更新文档，没有新增运行证据。

后续依次冻结逻辑记录的字节布局与正反fixture、连接源解码和有界资源读取、建立精确对象和时间映射、接入状态细化及版本提交、连接呈现回执、执行跨端测试。按[开发方案](../csg-world-video-interaction-quotient-plan.md)记录逐相内存与完整成本，按[知识产权规则](csg-semantic-video-ip-policy.md)复核实际采用的实现。

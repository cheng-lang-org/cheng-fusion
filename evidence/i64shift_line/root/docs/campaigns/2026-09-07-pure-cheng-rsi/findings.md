# RSI 发现

2026-09-07，只读源码审计 + 首版实现实证（载具 stage3，darwin arm64）。

1. RSI 需要已更新的改进机制实际参与下一代。当前 SGD、版本递增、工件登记各自都不能证明该关系。（设计期结论；本轮以 M0→M1 meta_accepted 实证了该关系。）
2. 现有 DiLoCo 线性训练与缩小图 lm_head 训练可作为后续限定适配器；不支持据此承诺全模型自训练。
3. 现有推理生成路径需要实际权重与算子覆盖证明；首版生成器=限定语法空间结构化搜索器（如实声明，非 LLM）。
4. 进程树资源守卫与文件/网络权限隔离是不同要求；首版只接了 argv 直传+超时硬杀+scratch 生命周期，RSS 硬限留待 beat_c 正式接线。
5. GEN2 自烤内存超限为既有记录；编译器域 C1-C5（编译时间/内存峰值/最小编译内核/运行时性能/语法优雅符号化直觉，2026-09-07 用户定谳）解锁前置（2026-09-08 纠正后分域化）=试验准入按维独立（固定语料语义指纹对拍+全门禁绿+该维严格更优；C3 另加自举链闭合，C5 另加 spec 迁移探针）+五维冻结测量合同；GEN2/GEN3 原始字节固定点降为发布级证据，不是试验前置。
6. **cold 链六墙**（lessons.md 2026-09-07 条目，probe1-9e 定谳）：形参/call-result 外呼须 Fmt；var 形参函数返回值不可信（Into 模式）；struct 禁 call-result 初始化（本地零值构造）；**连续两次 strutil.Split 产物内容损坏**（手工扫描+CloneStrRange 规避）；托管 struct 值形参 move 整表；**add() 构造数组不可传参**（argv 只能实参位内联字面量）。六墙皆 codegen 缺陷，归编译器战役修 realizer，业务规约不是语义。
7. 实测分数轨迹：bubble 2016 → insertion 1073（accepted）→ shell(16,8,4,1) 297（M' 后继，一次前瞻只评价不采纳）→ 下一轮 M1 当值将真实把 A 推向 297；平分拒收为合同正例实测。
8. rsi_gate 幂等性靠私有账本 artifacts/rsi_gate_store 每次清场重建，不触碰 artifacts/rsi 生产谱系；引擎收尾清场 + gate 收尾删大对象（exe/map），证据只留文本账本。

9. CSG 库层（merkle_dag/json_canonical/json_field/jsonl）在 stage3 下编译运行全绿（probe_csg1-3 实证）：" 转义可用、自定义 kind 行 DAG 层接受、DAG struct 值传参正常、add 构造数组可传 BuildFromCanonicalLines、Split 产物不可传（jsonl.CsgCoreJsonlSplitLines 权威切分替代）；生产 CLI 链在 launcher 接线前 HARD_RED，可控性只能落在库层。
10. 跨进程 run 的轮次 tag（g{round}_c{c}）在第二次 run 重复 → DAG duplicate key → 记账 rc=3 + verify 重放拒（gate 6/8 实测）；tag 改由事实行数全局单调派生（t{seq}_c{c}）根治。

11. 生产账本连续运行实证（2026-09-07 四段）：三轮连跑轨迹 gen0(2016)→gen1(1073, A 严格降分)→gen2(M0→M1 meta)→gen3(297, M1 模型兑现——白盒模型用学到的观测表选归并族)；verify 双链全绿（events 25 行 + CSG 重放五合同 + 账本三重对拍）。
12. 账本根快照滞后缺陷（生产三轮实测暴露，gate 单轮场景测不出）：版本提交后同轮 meta 后继评价仍追加事实，收尾根与提交点根不一致 → verify R1 全集根对拍必拒。修复=engine 收尾重算全集根同步 current.txt（与重放 R1 口径对齐）。教训：python 替换补丁必须断言匹配成功（本轮一次静默未落地导致一轮无效复跑）。
13. 已知缺陷（不阻塞持久账本，登记待下批修）：进程内 RsiTrialTable 流转全部未落位（done 行 pending=trials 计数，18/18）——流转写疑似被 codegen 吞（与 lessons 六墙同族候选）；持久谱系与判定不依赖该表（events 链与 CSG 事实均正确）。

14. 批次二三线并行（子代理文件面互斥+签名冻结）一次合流成功；主线程收口撞的墙全是「补丁锚不匹配+暴力替换双重叠加」——教训：python 替换必须 assert 锚+替换后 count 校验，禁止模式裸跑。
15. beat_c guard 是他线热文件（runtime py 被在飞 user_path_gate 线更新，sha 漂移+带写位触发 file_contract）；处置=停等收敛后恢复无写位合同态+经 BEAT_C_GUARD_EXPECTED_MONITOR_RUNTIME_SHA256（官方 env override）绑实际字节，gate 内同款绑定，不绕过任何自检。
16. RSS 理论极限模型（用户定谳）：ORC 确定性释放下同载具+同闭包的进程树峰值是可复现确定值；帽=冻结基线×3/2，基线随谱系持久且仅载具 sha 变化才重标（无滑动窗口——滚动会把漂移洗白，病理要抓的正是漂移）；实测 A 轮 182MiB/M 轮 186MiB，远低于 768MiB 平台硬限，理论帽把检出灵敏度提高约 5.6 倍。

17. M 档位竞争定谳（9/8 生产三轮）：M1 乐观界 4 代内到达变更空间 p=0 切面全局最优（归并 1127）；heap 2189/shell 2636/插入 5935/冒泡与选择 10640——族间分差在多任务聚合下清晰可辨；M2 纯利用 meta 同分被拒（合同正确）。改进器 order 只排族、前 maxCandidates 个全 param=0——param 维不可达不是缺陷（希尔任何 gap 档都劣于归并一个数量级），空间真收敛；下一提升面只能是变更空间本身（generator 演化）或编译器域解锁。

18. 收敛可证化（9/8 续）：exhausted 审计命令把「学完了」变成图上合同（覆盖矩阵+incumbent_min 对拍）；实测 6/18 PARTIAL + incumbent==best_correct——p=0 切面穷尽且最优在位。param 格不可达不是 generator bug 而是改进器输出函数的覆盖能力边界，审计将其量化——M 规则 4（param 遍历）的提案依据由此而来（盲区发现→规则提案→元评价裁决的完整元学习循环素材）。

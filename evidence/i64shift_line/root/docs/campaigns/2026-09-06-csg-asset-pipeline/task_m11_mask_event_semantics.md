## 1. 协议 v1 全文要点（MES1）

**语义变更（v0 → v1，消费者协议变更）**：

| 项 | v0（逐帧精确掩码） | v1（掩码事件化） |
|----|----|----|
| 掩码时间语义 | 每帧像素精确，逐帧再同步（v0 实测 1,925 次/224 帧，220,512B） | 事件时间戳生效；两事件之间掩码恒定（最后事件态外推），NoOp 帧零字节 |
| 参数时间语义 | 逐帧 FP16 Δ 精调（33,722B） | 不冻结，仍逐帧 FP16 Δ（参数连续驱动播放深度；掩码只定归属/拓扑）——探针 p0 变体实测参数冻结不可行（§5） |
| 事件类型 | —— | `PlaneBorn(tid,全参 f64,z,share,全掩码 RLE)` / `PlaneDeath(tid)` / `PlaneMutate(tid,参数Δ,掩码Δ=变化区域)` / `NoOp`（隐式：无事件帧） |
| 消费端承诺 | 逐帧逐像素精确 | 两事件间背景**不逐像素精确，但拓扑/结构正确**：平面集合、z 序、参数、面积量级连续演化 |
| 可逆性定义 | 逐帧重建 vs GT minIoU≥0.99 | ①关键帧解码与事件态逐位一致；②同容器重放（关键帧起逐帧应用事件，NoOp 恒等）得到**确定性的同一事件态序列**；③事件帧上被事件覆盖的平面掩码与编码源逐位一致、参数误差 ≤FP16 编码精度界（Δ 相对当前态，不跨帧累积） |

**容器布局（MES1，小端）**：`Header(magic/version/paramsMode/maskMode/maskEnc/gzFlags/trigIoU/W/H/frameCount/qmin/qmax)` + `KeyDir`（k225 口径，帧 0 关键帧 = v0 SPT1 关键帧载荷 gzip，与 v0 消费者锚点兼容）+ `Body(EventDir + ParamStream + EventSection)`。Mutate 掩码Δ两种编码：`bbox`（变化 bbox+局部 RLE）与 `global`（全帧 XOR RLE，v0 resync 同构）；Body 可选 gzip/lzma 整体压缩（顺序重放语义下随机访问由重放满足）。参数流记录为 flags 按需字段（f16 Δ=±0 与未变 z/share 不占字节）。

**探针变体**（事件触发是编码器策略，协议只管语法+重放语义）：`p1_struct`（掩码=仅结构帧，即 heir 链 death/birth 的 22 帧，其余 202 帧 NoOp——任务书主配置）、`p0_struct`（参数也仅事件帧，全事件化反证）、`trig*`（IoU(frozen,gt)<门即发事件，体积-质量曲线）、`_g`（全局 XOR RLE）、`_gz/_lz`（gzip/lzma）。

## 2. 信息论上界估算（估算，按 M9e 实测量做算术；与 §5 实测分开标注）

任务书估算式：`keys(7KB) + 24 transition×(变化 bbox+局部 RLE) + kept 参数微调 FP16`，逐项：

| 项 | 估算 | 依据 |
|----|----|----|
| 关键帧（帧 0） | 7,001B | M9e 实测（k225 单关键帧 blob） |
| 结构事件 adds/removes | 3,887B | M9e 实测（15 生 3,869B + 9 死 18B） |
| kept 参数逐帧 FP16 | 33,722B | M9e 实测（11.4 平面×13B×224） |
| 掩码事件（24 transition 受影响平面，局部 RLE） | ≈14KB | 估算：M9e churn Top 事件对平均 RLE ~600B/事件×24 |
| **合计（估算）** | **≈58.6KB** | —— |

**估算与实测的偏差归因**（两条，均由探针实测发现）：
1. 估算式假设「事件帧上只有事件直接平面变化」——实测 warm-start GT 的结构帧上**平均 9.6 个存活平面（212 条/22 帧）掩码全部有变化**（人物运动会扫过所有平面边界），且必须一次性偿还**冻结期累积漂移**（事件间平均 10.05 帧 × 漂移 ~29px/平面/帧 ≈ 单帧还账数百 px/平面），实测掩码事件字节 74.8-75.2KB，是估算值 14KB 的 5.3×。
2. 「bbox 局部 RLE ≪ 全局 RLE」不成立：漂移沿边界弥漫（bbox≈全图），实测 bbox 75,160B vs 全局 74,848B（差 0.4%）。

因此**诚实的先验上界（无压缩）≈110-115KB**（=实测 p1），<50KB 不可由「事件化+逐帧参数」直接推出，必须叠加编码压缩（§5：gzip 51.4KB 差 2.9%，lzma 43.6KB 过门）。

## 3. 质量语义明确化：NoOp 期间「平面边界位置冻结」的可见影响（全部实测）

- **漂移速率**（两事件间掩码漂移，frozen vs GT 逐帧实测）：全平面总漂移线性增长，lag1=403px → lag7=2,853px，**线性拟合 280.0 px/帧**（≈每平面 29px/帧，与 M9e 稳态边界抖动 39px/对/帧同量级，交叉自洽）。
- **事件间隔**：22 个结构帧贯穿 225 帧，间隔 mean=10.05 帧、max=36 帧（224/22=10.18）→ 单次事件平均还账 ≈2,815px 总漂移。
- **播放 MAD**（背景区 z 序口径，与 M9e 同构）：v1 全帧均值 6.794 vs v0 基线 5.917（**+14.8%，<20% 门内**）；f75=5.937/f150=6.825/f224=1.175。
- **越界区**（冻结过期后 v1 判背景而 v0 判前景的像素，最近平面口径深度误差）：f75=169px/23.7u8、f150=1,436px（全图 0.03%）/34.8u8、f224=0（f221 事件刚还账）。
- **消费端影响结论**：①背景-背景平面边界在事件间冻结，边界带深度归属滞后（误差 23-35 u8，集中在边界带，带宽随 lag 线性增长）；②冻结过期区可能覆盖真实前景——**合成顺序必须前景层优先**（M9b 前景流逐帧精确、前景覆盖背景，v0 已如此，协议将其升格为消费端必须项）；③参数流不冻结，深度值本身连续，无 p0 的崩溃。

## 6. 判词

**M11 交付，<50KB 判据 PASS（p1_struct_lz 43,565B），且两条先验假设被实测修正**：①掩码事件化把背景时间维从 266,781B 压到 43,565B（**6.1×**，无压缩口径 2.3×），播放 MAD +14.8%（<20% 门）、拓扑/结构正确、可逆=确定性重放+事件帧逐位——**M10 收敛的「掩码事件化语义」路线被证实为唯一达标路径**；②但任务书估算式（≈58.6KB）低估了事件帧「全部平面的冻结累积漂移还账」（实测 74.8KB，估算 14KB 的 5.3×），且 bbox 局部 RLE 对弥漫型边界漂移无增益（vs 全局差 0.4%）；③参数逐帧 FP16 流不可事件化（p0 反证：MAD +191% 崩溃），是协议的必要固定成本（~28KB raw）。**达标条件如实标注：43.6KB 依赖（a）本素材结构事件稀疏（22/224=9.8%，事件密度是体积主导变量）与（b）lzma 压缩 codec（gzip 口径 51.4KB 差 2.9%）**。

## 7. 立项建议

1. **立项成立**：v1 事件化语义（MES1）作为背景场景图时间维的 v1 消费者协议，判据建议订「背景时间维 <50KB（lzma）/ <55KB（仅 gzip）」，并要求**至少两个素材**复核结构事件密度-体积的线性外推（胡广生 22/224 → 容器 43.6KB；事件密度翻倍预计 +~18KB 事件区 raw）。
2. **消费端协议变更清单**（v0→v1）：掩码时间语义（外推）；合成顺序「前景层优先」升格为必须项；可逆判据替换为「确定性重放+事件帧逐位」；关键帧保留 v0 SPT1 载荷形态（兼容现有 v0 消费者锚点）。
3. **后续编码空间**（v1.1，非阻塞）：u16 runs → varint run 编码（掩码事件区实测平均 2B/run，短 run 占比高，方向性估算可再省 gzip 后 ~3-5KB）；参数流帧级 → 变长 Δ。

# task_m14_mes1_journey —— MES1 事件密度-体积外推第二素材复核（journey 600 帧）

日期：2026-09-13
工具：`tools/csg_mask_event_journey.py`（宿主 python/numpy；M11 参考编码器参数化复用，编码算法零改动）
产物：`artifacts/csg_asset_pipeline/journey/maskevent/`
上游：M11（MES1 协议 + 胡广生基线 43,565B，达标条件如实标注「依赖 (a) 结构事件稀疏 22/224 (b) lzma」）、M8c（journey BITEXACT 深度输入 + RANSAC 交叉验证）、M9e（warm-start GT 定义）

## 1. 目的与输入

M11 判据成立的前提之一待复核：「胡广生事件稀疏（22/224=0.098 事件/帧）需第二素材验证体积外推」。本任务用 journey（CSG 场景图渲染视频，600 帧 10fps=60s，棋盘格地面+条纹墙）跑同一 MES1 编码。

输入 BITEXACT 链（每次运行全量机械复核，非一次性手工检查）：
`depth_qp0.mp4`（H.264 lossless，sha256 对 manifest 断言）→ ffmpeg transpose=1 gray raw（M8c 同法，2026-09-13 单帧抽查 bitexact）→ `journey/semcov/depth_raw/` 600×32KB u8 → 逐帧对 run10fps npy f4 按 manifest 量化公式 `u8=round(d/1118.1397705078125×255)` 折算 + rot90(k=-1) 取向，600 帧逐位 assert PASS。

## 2. 方法（与 M11 严格同构）

- **GT**：M9e warm-start 跟踪式拟合（H=20），`fit_frame` 原样复用 600 帧；帧 0 = M8a/M8c RANSAC，对 M8c 记录的 frame 0 六平面（3 位小数）+cumCoverage 99.564% 硬 assert 锚定 PASS。平面数分布 5-16（25 帧撞 MAXP=16 上限）。
- **编码**：`csg_mask_event_codec.encode_variant` 原样运行，仅参数化 3 个模块常量（FRAMECOUNT / 量化域进容器 header / 关键帧 v0 JSON 元数据，schema 仍 v0）。变体 = M11 主口径 p1_struct(+_g/_gz/_lz)。
- **折算**：f112 / f225 截断容器为真实编码产物（非字节比例折算）；另算全量 60s 容器按时间比例摊 22.5s。
- **守卫**（每变体全过）：关键帧回读逐位、事件帧出生掩码逐位、参数误差 ≤FP16 界（maxErr 3.06 ≤ 界 4.98）、同容器二次重放确定性逐位。

## 3. 事件密度对照（真实运行）

| 项 | journey | 胡广生（M11） |
|----|---------|--------------|
| 结构事件帧 | 30/599 = **0.0501/帧** | 22/224 = 0.0982/帧 |
| 事件构成 | 死 13 + 生 21 | 死 9 + 生 15 |
| 事件间隔 | mean 18.57 / max 125 帧 | mean 10.05 / max 36 帧 |
| 逐帧掩码 churn（lag1 均值） | **275.5 px/帧** | 403.3 px/帧（线性拟合 280） |
| 单事件掩码Δ还账（raw） | 61,778B/30 = 2,059B/事件 | 74,848B/22 = 3,402B/事件 |
| 参数流（raw） | 60,947B/599 帧 = 101.7B/帧 | 28,099B/224 帧 = 125.4B/帧 |

**两个实测修正**（对「CSG 渲染背景恒定→更稀疏」直觉的精确化）：
1. journey 的稀疏稀在**结构事件**（warm-start 轨道稳定，结构帧少、间隔长），**不在像素 churn**——lag1 275.5px 与胡广生同量级，像素级背景并不恒定。
2. 单事件还账 RLE 更省（2,059 vs 3,402B/事件）：journey 漂移为刚体型大块位移（XOR 长 run，RLE 高效），胡广生为边界弥漫抖动（碎 run）。事件间隔长→单次还账漂移量大（lag124 均值 11,732px vs 胡广生 lag7 2,853px）但字节反而低。

## 5. 质量语义（如实）

- 播放 MAD（z 序）：v1 全帧均值 5.545 vs v0 基线 3.819（**+45.2%，超 M11 的 <20% 门**；胡广生 +14.8%）。归因诊断（v1 参数×GT 掩码播放 MAD = 3.819 = v0）：**退化全部来自掩码冻结**，FP16 参数舍入零贡献；长间隔（max 125 帧）末段漂移累积 1-1.4 万px。
- 掩码冻结越界区（最近平面口径）：f150=233px/24.96u8、f300=8px/13.44u8、f599=188px/46.60u8。

## 6. 判词：**通则**（MES1 达标不是胡广生特例），附两条边界修正

1. **外推成立**：journey 事件密度减半（0.050 vs 0.098），等时长（22.5s）容器 17.5KB < 胡广生 43.6KB，方向与幅度符合「体积 ∝ 事件密度×单事件还账 + 参数流固定成本」双线性模型；三种折算口径 12.4/17.5/24.8KB 全部 <50KB，且 gzip 口径（18.6KB）也过——**journey 上连 lzma 依赖都不需要**。任务判据（折算 22.5s 等效 <50KB）在第二素材上成立。
2. **修正一（稀疏的来源）**：稀疏的是结构事件而非像素 churn（lag1 275px 与实拍同量级）；事件密度低 = warm-start 轨道在渲染深度上更稳定 + 事件间隔长。体积优势的本质是「事件次数少 × 刚体位移 RLE 高效」，仍与 M11「事件密度是体积主导变量」自洽。
3. **修正二（60s 尺度的主导项切换）**：60s 全量整包 66KB 超门，主导项不是掩码事件（lzma 后 15.5KB）而是**参数流**（lzma 后 ~44KB，占 74%）——参数流是与事件密度无关的逐帧固定成本（journey 平面数 5-16、101.7B/帧 raw）。50KB 门推广到 60s 资产时瓶颈在参数流编码（v1.1 变长 Δ/预测编码方向），不是事件语义问题。
4. **质量守护后续项（不阻塞体积结论）**：长间隔素材上 MES1 播放 MAD 退化 +45%（>20% 门），协议消费端需事件密度下界守护（max-gap 约束或周期性强制事件），否则稀疏资产的质量语义劣化不被体积指标反映。

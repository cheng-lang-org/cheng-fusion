# CSG语义视频专利与实现选择规则

日期：2026年9月16日。适用于本项目的规范编写、参考实现选型及对外发布评审；不是新的数据载荷格式，也不是自动授予任何专利许可的声明。与[领域schema](csg-semantic-video-v0.1.md)配套，具体对照见[实施审查报告](../campaigns/2026-09-16-csg-semantic-video-patent-review/review_report.md)。

### IP-01 规范范围与技术选择

共同核心规定记录、身份、观测引用、时间、状态版本和错误语义。能力规范规定可验证的输入输出及失败行为。合规不要求采用特定的识别网络、重建模型、神经压缩方法、场景编辑服务或依赖缓存算法。算法、模型和第三方组件由实现配置清单精确标识并单独审查。

独立能力不是遇到失败时降低功能的路径。用户请求的能力无法满足时仍按原规范失败；不得为避开审查而删除必需状态、关闭完整性检查或将失真的画面标为合格。

### IP-02 语义定位与媒体载荷

对象标识、语义属性和观测定位保持独立字段或类型化资源。标准不要求把对象ID写成逐像素颜色、生成与原视频同尺寸的语义参考视频，或通过视线采样颜色取得语义。采用此类具体编码及交互流程时，应核对相关生成和播放权项。

标准不指定语义分段的神经网络结构，也不指定跨视点预测消息或运动网格。采用何种载荷编码不改变对原观测、未知范围、时间映射及实际解码结果的要求。系统编解码接口、开源实现和模型授权均须单独核对许可范围，不能据此推断全部第三方专利已获许可。

### IP-03 恢复、补偿与缓存

恢复正确性以精确基态、完整依赖及执行描述为准；补偿只作用于声明的表现域，且必须在实际输入下满足适用条件。标准不强制通过跨帧时间污染列表、原地更新缓存值或特定脏标记传播来实现上述要求。

不可变检查点、版本化依赖和完整输入比较是工程选型依据，不因使用这些术语就自动排除等同覆盖。引入跨帧缓存或优化前，须记录真实读写、更新顺序及与相关权项的区别；不能仅改名或换语言。

### IP-04 实时传送与协作编辑

直播需要流身份、世代、发布顺序和精确基态；规范不因此要求“编辑客户端上传场景差量、服务端分配全局顺序、回传该客户端并按该顺序同步场景”的协作架构。发布端提交序号与客户端协作编辑排序的角色应分别描述。

双向协作、多方场景合并、服务端排序回传作为独立实现配置审查。单写入者或本地分支本身不构成不侵权证明；实际部署具备相同或等同处理链时仍须对照。不得把未经审查的云端编辑模块隐含为直播合规的必装依赖。

### IP-05 空间重建与外部动作

空间能力声明来源、坐标、误差和支持域，不强制特定神经重建或对象模型替换算法。视频重建后的对象识别、呈现及交互修改要与各类独立权项分别对照，不能只检查是否使用资产库替换。

世界执行不强制强化学习训练和真实设备动作闭环。外部动作仍须独立身份、授权与实际回执；若产品确实提供这类闭环，另审查相应权利要求及模型实现。

### IP-06 权利披露与许可边界

标准维护方记录其拥有和知悉的相关专利及申请，至少列出权利人线索、申请/公开号、地区、核查日期、相关条款及许可声明来源。自有申请、共同申请和第三方权利分列；公布、实审、授权、有效维持分别表述。

本项目尚未作出向公众免费或收费许可的承诺。未来加入标准组织时，按该组织知识产权政策履行披露和许可程序；不能把本规则当作FRAND承诺、专利许可合同或权利人放弃权利。许可必须核对产品、主体、地域、期限、行为及分发范围。

### IP-07 对外发布评审

每个拟发布实现应有独立的审查记录，包含：规范版本和文件哈希；源码、二进制及模型版本；功能和角色时序；服务器、终端及销售地区；相关有效权项逐特征比对及等同问题；登记簿、同族和审查档案核验；组件及专利许可依据；结论适用边界、负责人和日期。

结论分为“有证据支持的未落入分析”“已取得适用许可”“权利失效经核实”“未解决”。尚缺资料的事项保持未解决，不填通过。未解决事项涉及拟发布功能时，不作该功能实施自由已确认的商业承诺，先完成针对性设计审查或许可处置。本规则不是播放时的法律判定器，不向v0.1记录新增字段或错误码。

### IP-08 变更后的复核

算法、载荷、缓存、网络角色、交互方式、模型或实施地域变化，以及相关申请授权或权项变化时，应在下一次相关发布前更新对照。把算法改为可选、将模块放到云端、改用Cheng或取得自有改进专利均不能直接关闭第三方权利风险。技术合规、可专利性和实施自由分别给出结论。

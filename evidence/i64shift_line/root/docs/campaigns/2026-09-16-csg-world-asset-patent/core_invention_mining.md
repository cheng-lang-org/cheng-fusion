# 存量视频转CSG世界视频的核心组合挖掘

日期：2026年9月16日。性质：研发与专利选题分析，尚非可直接提交的权利要求书。本次没有修改既有Word，没有执行新实验，没有提交申请。

核心候选：保真回放与交互执行共用的世界编码。把存量视频编译为能够恢复原片、接受世界干预、按需分发的执行状态；用状态与观测的适用关系共同决定压缩复用、交互失效和播放依赖。

这是一项拟研发的组合方法，不是已经证明“无法绕过”的独占技术。必须解决的工程问题可以有多种实现；申请能否成立还取决于具体方法相对现有技术的区别、创造性与充分公开。

## 一、从需求倒推三个共同约束

| 用户要的效果 | 必须解决的问题 | 可挖掘的具体机制 |
|---|---|---|
| 存量视频显著压缩且保留原片质量 | 省去的信息必须能由接收端已有信息重建，或者在预先定义的误差内省略 | 世界状态预测与观测补偿共同编码；以真实接收端重建结果判定复用区间和更新位置 |
| 秒开、跳播、恢复互动 | 目标画面依赖的状态、资源和执行能力必须已经可用 | 依据同一状态依赖记录，组织依赖完整的恢复单元，并约束传输、解码、状态恢复和实际呈现的总成本 |
| 看原片时保真，改动后可交互 | 原片的运动、阴影、遮挡等记录不能错误覆盖新的世界状态 | 对观测补偿和状态驱动分别登记适用条件与写入权限，干预后重新判定依赖，撤销已失效的原片补偿 |

三个问题之间有真实冲突：减少更新会增加画面误差及恢复链长度；增加独立恢复点会增加体积；保留原片补偿能改善原片画质，但在改变物体、灯光或遮挡后可能造成错误。值得研究的贡献是解决这些冲突的算法，而非把三个功能并排列入说明书。

## 二、核心候选的具体结构

### 1. 世界状态、观测补偿与执行状态分开表达

输入视频有明确的字节来源、帧序号、时间基准和可用相机信息。重建结果包含持续对象身份、几何与外观、时序状态，以及有依据的运动或物理参数。视频没有确定的信息不能标成恢复事实；交互使用的额外参数应有独立的假设或资产来源。

观测补偿表示基准世界渲染结果与参考视频之间仍需编码的差异，可采用像素、特征或其他明确的补偿形式。它属于编码本体，不是掩盖模型失败的事后补丁。其有效性至少绑定基准状态、参考视图和时间、渲染实现与数值配置，以及可复用的支持范围。

补偿只能作用于声明的输出域，不能反向篡改物理状态。视频轨迹驱动与物理求解对同一状态字段的控制必须明确，发生干预时不能同时由原片轨迹和新物理结果写入位置。

### 2. 用可检验的适用关系连接三个环节

对每项编码数据保存直接依赖，并按需要得到传递依赖；记录对象集合、空间查询范围、空查询等能够改变依赖集合的输入。不能只记旧画面中可见的对象，否则新增遮挡物、光源或接触对象可能遗漏。

同一依赖关系参与三个决定：编码时哪些信息可以省略；恢复某一播放状态时哪些数据必须到齐；发生世界干预后哪些旧状态与补偿还能使用。

精确输入相同且执行合同相同时可以验证复用。扩大到不同视角、不同状态的补偿复用，需要额外的有效域证明或限定测试依据。单目视频不能自动给出完整的真实因果依赖，不能用一次拟合或一个哈希冒充证明。没有成立的适用依据，就不能把旧补偿用于新状态。

### 3. 编码分段与恢复分段联合决定

对有限输入序列，预先定义参考分辨率、帧率、误差指标与阈值、目标设备、网络条件和内存预算。每个候选恢复单元都必须有可独立解析的入口，以及足以恢复声明状态的完整依赖；缓存命中只扣除已经核验存在的精确依赖。

候选单元经过实际解码和呈现验证后，才进入分段选择。对于代价与约束可按区间分解的有限候选集合，可以用动态规划求该集合内的最小总字节分段；若存在跨段共享或其他不可分解依赖，应显式纳入优化模型，不能继续声称简单动态规划全局最优。此算法类别本身已有大量先例，不单独作为新颖性主张。

首帧目标计算到实际呈现，包含建链、取数、解码、恢复、渲染和呈现。网络预算是前提，不构成任意网络条件下的硬时延保证。“秒发”还要分开计算上传、服务端可用、接收端可取与原始视频转换耗时；一个根地址生成很快不等于数据已经发布可用。

### 4. 干预、恢复与呈现保持同一分支

接收端先检查恢复单元及依赖，再恢复完整状态。完整状态可能含速度、控制器记忆、求解器历史和随机流位置，不只是位置截图。

用户干预产生新分支。受影响的状态驱动、原片补偿及派生输出按依赖重新判定；仍成立的资源可复用，需要改变的部分重新执行。新分支的画面、交互碰撞和音频事件引用同一已提交状态，不能混用旧分支阴影或轨迹。

从原片恢复出来的物理模型仅在其声明能力范围内执行。原视频未观察到的背面、遮挡内部以及新动作后果属于重建假设或模型输出，不能宣称逐像素恢复了真实历史。

## 三、一个能暴露组合价值的例子

存量视频是一只球落到桌面上。播放原片时，用世界运动与外观编码加上必要补偿达到约定画质。用户跳到中段，需要恢复球的速度和相关执行状态，不能只加载球的位置。用户把桌子移开，必须撤销已经不成立的桌面接触、反弹轨迹、接触声音和原片阴影补偿；球根据新世界继续运动。

这时压缩、跳播和交互并非独立模块：如果编码时没保存恢复必需的信息，跳播后无法正确执行；如果补偿没有适用条件，原片图像会覆盖交互结果；如果每次都重新下载或重建全部世界，分发和响应成本可能上升。上升多少必须实测，不能预先填百分比。

## 五、绕开检验

| 替代路线 | 是否可能 | 需要验证的取舍 |
|---|---|---|
| 整段普通视频播放，交互另建游戏场景 | 可以绕开共用编码路线 | 同一画面与可执行状态的连续性、转换成本、重复资源量 |
| 云端执行世界，只给用户传像素流 | 可以改变端侧恢复和分发路线 | 网络依赖、每用户计算开销、端到端交互时延；不能预言一定更差 |
| 使用NeRF、3DGS、网格或其他表示 | 可以替代几何底层 | 核心方法若只限定某种几何或品牌名称，容易被替换；扩大范围须有说明书支持 |
| 每个访问点存完整快照，每次修改全量重算 | 可以避免精细依赖复用 | 存储与计算代价可能上升，但有些规模下可能更简单、更快 |
| 原片回放与交互分支采用不同渲染表达 | 可以 | 需要处理切换一致性，但不必采用本候选结构 |

因此目前没有依据称任何一项“无法替代”。竞争目标应是：同等质量、能力和设备条件下，替代方案需要付出可量化成本。即使证明性能优势，也不自动意味着专利覆盖替代方案。

## 六、现有进展与必须补做的验证

现有M14记录是一个具体动机：结构事件稀疏时背景编码体积下降，但播放深度MAD相对基线增加45.2%，超过该任务20%的门限。说明只以结构事件决定更新时间不能保证该素材的质量。它不证明本文方案已经解决问题，也不是RGB原片质量指标。

M12是有限镜头、低分辨率输出、保留base.mp4纹理的实验；此前双设备报告也未证明跨设备全链秒开。不能把这些实验加起来当作本组合已实现。

最小验证应固定同一输入、输出质量、设备和缓存状态，同时比较：

1. 顺序播放和跳播的输出误差，以及全部必须依赖的字节量。
2. 首次点击到实际首帧、跳播到首帧、操作到新分支呈现的时延。
3. 无关修改保留合法复用，有关修改撤销失效补偿；新增遮挡、光源、接触以及空查询转非空都要覆盖。
4. 中途恢复后的运动与从同一分支初态完整执行一致；复用路径不能读取全量对照的缓存。
5. 分别去掉补偿适用关系、编码恢复联合分段、完整依赖记录，检验其带来的错误或成本变化。消融实验用于证明组合效果，不预设一定胜出。

千倍压缩必须分别报告完整冷包和缓存命中的新增传输量，并计入纹理、音频、模型及执行依赖。相对原始神经场、逐帧深度或无压缩像素的倍率不得写成相对成熟视频编码的倍率。

## 七、专利布局建议

优先候选名称：**一种基于观测约束和状态依赖的交互视频编码与恢复方法**。

先围绕“观测补偿的状态适用关系同时参与编码复用、恢复依赖确定和干预失效处理”建立一个可实施的核心，再决定独立项边界。首帧预算、网络协议、内容寻址、具体几何、音频共同提交等只有在形成必要技术关系时纳入，避免把所有功能塞入独立项而让实现者轻易缺少其中一个特征。

哈希或Merkle根只承担定位、完整性与版本绑定，不能承担世界真实性、物理正确性或观测适用性的证明。Cheng语言、CSG名称、某个渲染引擎、具体网络协议和“千倍”“秒开”效果词不应取代技术步骤。

资产能力准入与已有状态复用稿作为关联基础，保持不同的具体技术问题。只有新的编码恢复方法能够充分实现、与已有公开方案形成有依据的区别时，才值得另行申请。中国专利法第二十二条和第二十六条分别要求新颖性、创造性及充分公开；组合数量多并不能代替这些条件。
